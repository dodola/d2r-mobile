# Android 系统驱动分块提交验证

本批在 main 上继续兼容性与性能总目标。参考 ZeldaWWHDRecomp 的异步提交设计，
没有移植其 GX2/Latte 代码，也没有直接采用其 2,048 draw 阈值。它可以在达到阈值后
结束通道，咱们只在已有必要通道边界尝试提交，两者的阈值含义和生命周期不同。

## 实现与不变量

- 新增诊断控制 `diagnostics/chunk-control.txt`，格式为递增序列号和阈值。
  只有文件在启动时存在才启用轮询；普通启动不读这个控制文件。
- 请求最多每 100 ms 读取一次，在下一个 submission 开始时锁存；正在记录或飞行中
  的 slot 保留原阈值。0 关闭中途提交，诊断范围 0–2,048；默认仍为 48。
- 日志分别记录接收请求和实际采用的序列号、阈值、epoch 与单调时钟。
  每个 slot 的临时资源、命令池、描述符和写回仍由最终 fence 保护。
- 不增加为凑阈值而拆开的 RenderPass，不移除遮挡查询、GPU 写入和 guest 发布的保护。

## 系统驱动 GPU 正确性

Qualcomm proprietary，Build `923a446bf8, I23d7d7df15, 1725536844`。

`0,16,48,256,256,48,16,0`。每个模式执行 600 draw，交替两个颜色附件，
在 draw 100/300/500 前用 Compute 改写 GPU 顶点颜色。三个独立 scissor 区域保留
A/B/A 输出，检查 GPU 生产者顺序、跨 chunk 资源、绑定状态、背景保留和最终 CPU 写回。
两个着色器由测试编写，并经过 `spirv-val --target-env vulkan1.1`。

## 性能采样方法

覆盖安装原 Android shell 的 native 更新包，保留原签名、UID、ROMFS、存档和设置。
在同一 PID 的同一局营地中，按
`48,16,48,256,48,256,48,16,48,0,48` 交错采样，每轮实际显示采集 35 秒。
实际采用模式后等待三次 profile 窗口输出（首个可能混合，至少两个全新模式窗口），再开始计入；场景探针每约 5 秒核对区域、
玩家身份与坐标，并比较所有采样的场景身份。

帧率来自 SurfaceFlinger actual-present 时间戳；每轮记录绘制量、提交数、
管线编译、温度与热状态。候选与前后 48 基线按时间插值比较。采用标准为至少两次
重复、平均收益至少 3%、每次方向一致、绘制量变化不超过 1%、相同热状态且无编译干扰。
没有控制 GPU 时钟或证明热稳定；营地 NPC 状态仍可能影响负载。

中途提交取 `HZ_SYNC chunks`；`SEG0 chunks` 包括末尾提交，不能把 7/4 当成
7/4 次中途提交。每轮均等待真实 `CHUNK_MODE` 序列后才采样，期间没有模式变化。

相邻基线时间插值后，16 的两次平均相对差为 -0.007%，256 为 -0.512%，都不满足
采用标准。顺序 3 有 12.166 ms 管线创建，保留为受干扰样本；基线本身也有波动，
不能把这些微小差异解释为确定提速或退步。关闭中途提交的一次样本下降约 18.47%，
恢复 48 后回到约 16.96 FPS；该观察只有一次关闭样本，也不代表所有场景。

**保留默认 48，没有宣称本批带来 FPS 提升。** 进一步优化应继续定位 GPU Pass，
不按其他项目的 draw 数直接改默认值。原始记录与汇总分别是本地证据目录的
`camp-ab.json`、`summary.json`、`camp-*/`；`run_camp_ab.py` 和 `summarize.py`
保留执行及计算过程。

## 单独营地 GPU 时间采集

另启用 `profile-detail` 与 `pass-timing`，重启后进入营地，预热并采集 60 秒。
PID 11116，16 个完整 profile 窗口共 960 个 renderer 帧，实际显示 16.171 FPS。
期间有 11.755 ms 新管线创建；采样为诊断用途，不能与普通模式跨重启的 FPS 相减
推导改动收益，也不能称为完全无编译的稳态。

## 交付与恢复

移除本批创建的阈值、详细计时标记，重启为普通系统驱动模式。最终 PID 12777，
营地 60 秒实际显示 **16.583 FPS**，只作运行回归，不宣称提速。
截图无明显模型拉伸；这不是战斗或逐帧图像等价证明。

APK 为本地证据目录的 `D2R-Chunk-Diagnostics.apk`，SHA-256：
`c2a0e784bfb8fde38675631644689d147007606acb7840fdff0571bbc16e0365`。
native SHA-256：`3a4f2a04e6cea3fbfec458876c5fd2161b00d2c54381598b7e815259d9bb2c8c`。
覆盖安装、签名及 16 KiB 对齐检查通过，已核对设备实际映射的库与上述 native 一致。

UID 10200、ROMFS 8,973,693,207 字节，15 个存档/设置文件集合保留。
只有 `KKK.d2s` 和其 meta 因正常游戏保存发生变化；其余文件内容不变。
三个重点 Shader 的六个资源文件与之前备份逐字节一致。
只读验证过程与结果为 `verify_delivery.py`、`delivery-validation.json`。
