# GPU 写入范围读取诊断

本轮从 CPU profile 继续检查 `pool_read` 与脏页写保护开销。营地每 60 帧约有
数万次小范围读取；其中一部分读取范围已经被当前提交的 GPU 写入完全覆盖，CPU
不应再把 guest 内容上传到 Vulkan pool mirror。

实现了两个诊断开关：

- `diagnostics/pool-range-stats`：按读取大小统计命中、写保护和 uniform 范围。
- `diagnostics/pool-owned-read-bypass`：当当前提交的写入区间完整覆盖读取范围时，
  跳过该次 CPU 上传检查。范围覆盖检查处理无序、相邻、重叠区间和整数溢出。

在系统驱动、原始 Shader、原分辨率和固定营地下，启用诊断开关的两轮实测为
22.854 和 22.881 FPS；同一 APK 关闭开关的一轮为 22.700 FPS。启用时每 60 帧
统计约 67,620 个跳过范围、38.3 GB 逻辑读取，writeback prepare 从约 36,300
页降到约 20,820 页，writeback 子集 CPU 时间从约 118 ms 降到约 91 ms。
温度、绘制数量和设备时钟没有完全受控，因此这组 FPS 差异不足以证明稳定收益。

该开关保持**默认关闭**，只用于后续复测。设备 fixture 的 chunk/index GPU 回归均通过；
默认关闭版本覆盖安装后可正常进入菜单。当前版本没有把它作为发布默认行为，避免把
尚未完成跨场景验证的写入覆盖假设带入普通运行。
