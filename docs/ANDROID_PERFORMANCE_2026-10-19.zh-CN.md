# Android 原画质性能观察

日期：2026-10-19。设备：TNA-AN00，Adreno 642L，Android 60 Hz 显示模式，USB 供电，设备温度处于 Thermal Status 2。场景：D2R 3.3.94012 角色选择页，3D 比例固定 100%，内部和输出均为 1280×720。

## 驱动

- 系统驱动：Qualcomm Adreno Vulkan，driver id=8，驱动构建 `923a446bf8`，设备报告 `Adreno (TM) 642L`。
- 可选私有驱动：Mesa Turnip `26.2.3 (git-fbc44a3bcc)`，driver id=18；使用随包 `libadrenotools.so` 和 `libd2r_turnip.so`，实际渲染正常。
- 当前策略：系统驱动作为默认性能路径；Turnip 作为显式选项，不自动选择。

同一画面、同一 100% 设置、命令状态缓存开启时，系统驱动稳态约 12.2 FPS，Turnip 约 10.5 FPS。Turnip 首次启动还会重新编译管线，观察到约 9.4 秒的累计 pipeline 时间；这不是稳定的画面性能比较，但足以说明不能把 Turnip 设为默认。

## 100% 画面瓶颈

60 帧窗口的 pass timing 显示 GPU pass 合计约 3.8 秒，其中：

| 渲染组 | 类型 | 每帧 draws | 60 帧 GPU 时间 | 说明 |
| --- | --- | ---: | ---: | --- |
| `rt_key=70b52d91c` | 1280×720，颜色 1 | 约 386 | 约 2.35 s | 头发和模型两组 pass，占比最高 |
| `rt_key=1d` | 1280×720，深度 | 约 386 | 约 0.32 s | 深度输出 |
| `rt_key=89359ba59` | 1280×720，颜色 2 | 约 39 | 约 0.30 s | 后续颜色目标 |
| `rt_key=2e` | 256×256，深度 | 约 281 | 约 0.18 s | 阴影/深度辅助 |

头发 pass 的热点像素 shader 为 `ps_haIR` 对应的 `203a07...`，模型 pass 为 `ps_models_p` 的 `5c1ca4...`。两者合计约 385 次 draw，和最高耗时组吻合。它们使用同一 1280×720 颜色目标，但当前由原版命令流分成两个 render pass；在没有确认深度视图和依赖完全一致之前，不能直接把两者合并。

系统驱动的命令状态缓存默认开启后，60 帧窗口从“全部提交”变为约 336k 次跳过，100% 场景从约 11.8 FPS 提升到约 12.2 FPS。收益存在，但 GPU 等待仍在每帧约 40 ms，说明单纯减少 CPU 状态命令不足以突破这个场景。

## Turnip 路径

Turnip 的 sysmem 模式在同一 100% 场景约为 11.0 FPS，默认 GMEM 约为 10.5 FPS；差异不大，但 sysmem 更适合作为当前 Adreno 642L 的稳定调试基线。Turnip 本身渲染正常，日志为 `Mesa 26.2.3 (git-fbc44a3bcc)`、driver id=18。

Turnip 首次运行会创建约 2.12 MB 的管线缓存并向 125 个 PSO 预热。把同一驱动/设备的缓存作为 APK 种子后，首次启动读取到 `seed_bytes=2120741`，`PIPELINE_WARM_START entries=125`，首帧 `pipeline_ms` 约 0.85 ms；冷缓存时曾观察到数百毫秒到数秒的管线编译停顿。种子只会在应用私有缓存不存在时复制，native 仍会校验驱动 UUID、渲染 quirk、shader 链路和 PSO 版本，不匹配时自动丢弃。

## 结论

- 100% 原画质的主要限制是 1280×720 模型 pass 的 GPU 成本，不是驱动选择或单个 Java UI 绘制。
- 75% 自动/性能档可以改善 GPU 等待，但会降低模型边缘清晰度；90% 是新增的均衡档。
- 当前画面素材来自 Switch 版本，1280×720 放大到 2652×1200 会进一步放大粗糙感；提高内部比例只能改善边缘，不能增加原始纹理细节。
- 设备当前 Thermal Status 2、CPU 约 63–69°C，热限制也会压低持续帧率；性能数据不能当作冷机峰值。

后续原画质优化应优先做 pass 级合并和模型 pass 的 GPU 工作削减；输出分辨率必须与 3D 比例分开实现，不能只把 1280×720 的输出目标整体放大。Turnip 开发基线使用 sysmem、命令状态缓存和种子管线缓存；系统驱动保留为性能回退。
