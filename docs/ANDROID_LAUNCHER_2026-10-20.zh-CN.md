# Android 启动器交互优化

本次修改位于 `codex/android-integration-optimizations`。仅进行代码和主机离线验证，没有连接设备或验证真机页面效果。

## 页面与操作

- 资源状态、阶段进度、空间提示和主按钮集中在首屏卡片。检查、导入、停止中、完成安装、就绪和错误都有对应反馈，重复点击不会重复创建任务。
- 导入完成后停留在入口，明确点击“启动游戏”进入；不再自动跳转。就绪卡片列出驱动、MOD 和存档模式。
- 图形驱动和 MOD 收入默认折叠的“启动设置”；安装和存档说明独立折叠。驱动保存失败时回显已保存选项，并单独提示，不覆盖安装状态。
- 启动前可选择已安装 MOD 或关闭 MOD；所选包缺失、选择文件损坏时，在入口引导重新选择。这里沿用现有 MOD 包和隔离存档机制，不增加手机端 MOD 包导入器。
- 停止按钮和返回键先确认；关闭确认框会继续导入。安装结果提交期间不允许取消。取消与提交相遇时，以已经进入的不可取消提交为准，完成后显示就绪。
- 取消文件选择器不改变现有资源状态，并允许重新选择。失败或停止后重新选包，沿用底层导入器的已校验文件复用。
- 切到后台、旋转或重建页面不会主动取消进程内任务。没有新增前台服务：系统回收进程后仍需要重新选包。仅页面在前台且正在处理资源时保持亮屏。
- 内容按实际窗口宽度布局，最大 600dp；隐藏无效进度条和停止按钮。使用系统按钮、单选组、对话框与可滚动页面，保留键盘焦点、无障碍标题和状态播报。

## 离线验证

运行以下命令（JDK 路径沿用工作区既有工具配置）：

```powershell
$env:ANDROID_SWITCH_WORKSPACE='D:/AndroidSwitch'
$env:D2R_ANDROID_SOURCE_ROOT='D:/AndroidSwitch/runtime/d2r-mobile'
python tools/d2r-mobile-port/verify_offline_installer.py
```

覆盖原导入器 40 项、启动任务状态 21 项、MOD 选择 20 项及图形驱动策略。新增状态测试包含重复导入、并发启动、取消后重试、真实导入器回调中的取消，以及取消与持久化提交相遇。另编译全部 Android Java 源码并检查 DEX 转换。

真机后续需要确认：小屏和大字体滚动、横竖屏与文件选择器往返、系统回收后重选包、导入中确认/取消、MOD 异常恢复及首次游戏启动。发布说明和安装指南生成器的操作文字已同步；指南中的设备截图仍是旧版截图，未生成或宣称新版实测截图。
